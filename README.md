# My Home Clone

ブラウザで動く、完全ローカル完結型の **3D間取り・家具配置シミュレーター**。
注文住宅の自己検討ツール。将来的に **日射・日当たりシミュレーション** を独自機能として追加予定。

> 「マイホームクラウド」「住宅スキャン」は他社登録商標。本プロジェクトは個人利用で、名称は **My Home Clone / マイホームクローン** を用います。商用配布はしません。

## 技術構成

- 純粋なフロントエンドのみ。**ビルドツール・バンドラ不要**（Vite/webpack なし）。
- ES Modules（`type="module"`）でファイル分割。
- 3D は **Three.js** を CDN + importmap で読み込み（npm 不要）。
- 永続化は **LocalStorage 自動保存** ＋ **JSON エクスポート/インポート**。
- 外部送信・サーバ通信は一切なし（完全ローカル）。Three.js の CDN 取得のみネット接続が必要。

## 起動方法

VS Code / Cursor の **Live Server**（Port 5500 想定）で `index.html` を開くだけ。
または任意の静的サーバで配信:

```bash
python3 -m http.server 5500
# → http://localhost:5500/
```

※ `file://` 直開きは ES Modules / importmap の制約で動かないため、必ずローカルサーバ経由で開いてください。

## 開発時の静的チェック（任意）

ランタイムは引き続き npm 不要です。コード変更後に **構文エラーや変数の二重宣言** を検出するには、開発用に ESLint を使えます:

```bash
npm install   # 初回のみ（devDependencies のみ）
npm run lint
npm test      # 敷地ロジックなどの単体テスト（Node 標準の node:test。追加依存なし）
```

`no-redeclare` などにより、同一スコープ内の `const` 重複（プラン新規作成不能の原因になりやすい）をコミット前に検出できます。

## 座標・単位の規約

- 内部単位は **mm**。`X`=間口（左右）、`Z`=奥行（上下）、3D の `Y`=高さ。Three.js の Y-up 右手系に一致。
- 1マス = **1P = 910mm**。スナップ = `910 / snapDivisions`（既定 4 = 0.25P / UIで 0.5P・0.25P 切替）。
- 面積はシューレース公式で算出し m² に換算。畳数 = 面積(m²) ÷ `meta.tatamiM2`（既定 1.62）。
- 図面表示は「12.4㎡（7.6帖）」形式。

## 使い方（フェーズA）

1. 上部で **2D / 3D** とフロア **1F / 2F / 3F** を切替。
2. 左の **ツール**で操作を選択:
   - **部屋を描く**: 種別を選び、作図エリアでドラッグして矩形の部屋を作成（壁は外周に自動生成）。
   - **家具を置く**: 家具を選びクリックで配置。
   - **選択 / 移動**: 部屋・家具をクリックで選択、ドラッグで移動。`Del` 削除、`R` 家具回転。
     選択中の家具を右クリック（または短クリック）すると、**左右反転・上下反転**・削除のメニューが出る（反転は家具自身の向き基準の鏡像で、2D・3D に反映）。
     未選択の家具も右クリックで選択され、プロパティ（寸法）が表示される。
     **建具**（窓・ドア・間口など）は選ぶと両端に白い丸が出て、ドラッグで幅を伸縮できる（グリッドにスナップ、最小 100mm）。プロパティの「幅 (mm)」でも数値指定できる。
     ただし階段の出入口に自動で付く間口（`autoStairId` 付き）は、階段を動かすと自動の幅に作り直される。
   - **階段**: 種類は直進（1P×3P、2D は「UP」表示）・L字階段（上で回る / 下で回る、回り段付き）など。L字系はプロパティの「曲がる向き」か右クリックメニューの「左右反転」で鏡像にできる（`stair.mirror`）。
     階段の出入口の辺が部屋の壁に接すると、その壁に**自動間口**が開く（`syncStairWallOpenings`）。ただし階段がその部屋の中にあり、壁が外壁の場合は外へ抜けるので開けない。
     階段の辺のうち建物の外側に面する部分には**外壁**が付く（`stairExteriorWallSpans`。2D・3D とも）。
     上がってきた階段の上の階に部屋も階段もない場合（最上階など）は、その位置にも外壁・天井・屋根が付く（`stairTopCapRooms` が仮の部屋を作り、屋根計算にだけ使う。面積や壁データには入らない）。
     左の「屋根」パネルで、**屋根の形状**（陸屋根 / 寄棟）・勾配（寸）・軒の出を選べる（建物全体で 1 つの設定。plan.roofSettings）。寄棟は、階の部屋全体の形で作り、上の階の構造がある部分をくり抜くので、階段状に重なった家でも、各階の「上が空いた部分」に屋根が付く（L字・T字など直交する壁の平面に対応。階に斜めの壁の部屋が混ざっていてもその部屋だけ平らな屋根にして残りは寄棟にするが、上の階の構造そのものが斜めの場合はその階全体が平らな屋根のまま）。軒は日射の遮蔽にも反映される。3D の「屋根: 表示中 / 非表示」ボタンで、寄棟メッシュと各部屋の半透明の天井パネルをまとめて隠せる（影・日射の計算は変わらない。屋根も上階もない部分では、床がそのまま外から見える仕様）。
     バルコニーの部屋を選ぶと、プロパティで **手すりの高さ**（屋外側の壁。既定 1500mm、300mm〜天井高）を部屋ごとに変えられる。居室と共有する壁は天井高のまま。
   - **画面移動**: ドラッグでパン（ホイールでズーム）。
   - **敷地を描く**（左の「敷地」パネル）: 下絵に沿って頂点を順にクリック → `Enter` か始点クリックで確定（`Shift` で 45° 刻み、右クリック/`Backspace` で直前の点を取り消し、`Esc` で中止）。確定後は枠線をクリックして選択し、プロパティで **辺の長さを数値指定**、頂点のドラッグ、右クリックでの頂点追加/削除ができる。辺の長さ・内角・面積（㎡/坪）を常時表示するので、下絵の縦横比がおかしくても実寸に合わせて書き直して下絵を非表示にできる。敷地に接する壁は外壁として扱われる。
   - **下絵の回転と方位**（ツールバーの「下絵 ▾」。基準線で実寸合わせした後に出る）: 「線をなぞって水平に」で敷地の辺などを 2 点クリックすると、その線が水平（または垂直の近いほう）になるよう下絵を回す。回転角は数値でも入力できる。回すと、描いた敷地と方位（`site.azimuth`）も一緒に回るので、真北の向きは変わらない（部屋・壁は回らないので、間取りを描く前に合わせる）。「方位記号から北を指定」で下絵の方位記号を根元→先端の順にクリックすると北が決まる。2D 右下の方位マークと 3D の日射は `site.azimuth`（図面の上から真北への時計回りの角度。`js/siteOrientation.js`）を使う。
3. 各部屋に **面積㎡と帖** を自動表示。
4. **3D** で壁を天井高まで立ち上げて立体表示（OrbitControls で視点操作）。形が分かりやすいよう、壁・屋根に輪郭線を描き、カメラに付いた補助光で陰影を付けている。**内観モード**で160cm目線の一人称歩行（右上ミニマップ・左下で階ワープ）。
5. 変更は **自動で LocalStorage 保存**。**JSON書出 / 読込** とプランの **新規・複製・削除** が可能。

## ロードマップ

- **フェーズA（実装済）**: 2D作図・面積/帖・家具・階段・3Dビュー・永続化・JSON入出力・プラン管理。
- **フェーズB（実装済）**: 日射シミュレーション。
  - `js/sun.js` に NOAA 準拠の太陽位置計算（外部ライブラリ不使用）。`getSunPosition(date, hour, lat, lng)`。
  - 3Dビューで `DirectionalLight` を太陽位置に連動・影（shadow map）を有効化。`site.azimuth` を建物回転に反映。夜間は太陽光を消灯。
  - 日射UIパネル（日付/時刻スライダー・季節クイック移動・太陽情報・1日アニメ再生・緯度経度/方位角）。
  - 各部屋の直射日照時間を `Raycaster` で集計し、2Dの部屋ラベルに「☀ 5.5h」表示。座標既定は板橋区赤塚（北緯35.775 / 東経139.679、`meta.lat`/`meta.lng`）。
- **フェーズC（一部実装済）**:
  - 実装済み: 建具の拡充（間口・FIX窓・片引き・引違2/3枚）、住設の家具配置（便器・ユニットバス等）、
    敷地写真の下絵トレース＋実寸の敷地作図（`js/sitePolygon.js`）、下絵の回転と方位指定（`js/siteOrientation.js`）、追加壁（`floor.partitions`）、
    寸法線表示（`#dim-toggle`）、バルコニーの手すり高さ調整（部屋ごと）、寄棟屋根（`js/roofModel.js`）、
    階段の種類追加（L字・左右反転）と外側の外壁・上階の天井/屋根、3D の輪郭線と補助光、建具の幅のドラッグ伸縮。
  - 未実装: 外構の配置機能、片流れ・切妻屋根、PDF/画像書出、kWh単位の取得熱量概算。

### 既知の制限・次の候補（次のセッション向けメモ）

- **屋根:** 寄棟のみ対応。次点は片流れ屋根（下屋・上階に接する部分向け）、切妻屋根。
  上の階の構造自体が斜めの壁を持つ場合、その階は屋根をくり抜けず平らな屋根のまま（`reason: 'non-rectilinear-upper'`）。
- **屋根がない部分の床:** 屋根・上階のどちらもない部分は、3D で床がそのまま外から見える（ドールハウス的な仕様）。
  「隠したい」という要望が出た場合は、屋根の表示切り替えと合わせて検討する。
- **キャッシュ:** GitHub Pages は最大10分キャッシュされるが、`sw.js`（service worker）が同じサイトの
  ファイルを毎回サーバーに確かめてから使う（ネットワーク優先・オフライン時のみ前回の内容）ので、
  公開後にアプリを開き直すか再読み込み（Cmd+R）すれば新しい版になる。ただし service worker が入る前の版を
  開いている端末では、最初の 1 回だけ従来どおりの手動更新が要る。デスクトップアプリ（Safari ベース）は
  Cmd+Shift+R がリーダー表示のショートカットと衝突するため効かない。手動更新は
  Option+Cmd+R、または Safari の「開発」メニュー→「キャッシュを空にする」（⌥⌘E）を案内すること。
  ビルド版が分かるよう、画面に版数を出す案がまだ未着手。
- **階段:** 階段のローカル辺は 0=−Z（上がった先）、1=+X、2=+Z（入口）、3=−X。種類の定義は `js/catalog.js` の
  `STAIR_TYPES`、2D 記号は `js/stairDraw2d.js`、3D の踏み板・囲い壁は `js/viewer3d.js`、開口の位置は `stairOpenEdgeSpans`（`js/model.js`）。
  種類を増やすときはこの 4 か所をそろえる。
- **3D の見た目:** 輪郭線と補助光で立体感を出したが、本人の評価は「ゴテゴテだが、とりあえずこれでいい」。
  線の濃さ（`OUTLINE_MAT`）や光の強さは調整の余地あり。
- **開発フロー:** 変更は `npm run lint` と `npm test`（`tests/*.test.mjs`）で確認してから
  コミット・`git push origin main` で公開（GitHub Pages）。実機確認はブラウザ操作で行い、
  変更前後の日射時間などの数値を比較して回帰がないことを確認する運用で進めてきた。
